# 部署说明

正式公开入口：https://mengniu-opportunity.coze.site/

## 应用边界

```text
浏览器 → 本仓库 Node 网页服务 → 原扣子 Agent 的访客隔离接口
                                  ├─ 模型与资料检索
                                  └─ 访客 PostgreSQL 存储
```

网页归档从 `public/cases.json` 读取。真实任务经 `/api/bridge` 转发至 `https://mengniu-agent.coze.site/visitor/v1`，不会访问原开发预览中共用“当前任务”的接口。这里只提供网页及代理工程，不是完整离线 Agent。

## 扣子网页工程配置

将本仓库作为网页工程导入，使用根目录 `.coze` 和 `scripts/` 中的构建、启动配置。工程无需安装运行依赖。导入操作是否自动启动平台编程助手，取决于扣子当时的产品流程。

生产环境配置：

| 变量 | 用途 |
| --- | --- |
| `MENGNIU_AGENT_API_TOKEN` | 有权调用原 Agent 访客接口的 API Token，仅存平台服务端 |
| `PUBLIC_ORIGIN` | 可选，填写最终 HTTPS 网站源地址，不加末尾斜杠；用于限定提交来源 |
| `PORT` / `DEPLOY_RUN_PORT` | 服务端监听端口，按托管平台要求设置；代码默认 5000 |

扣子在本次部署时不允许自定义变量名以 `COZE_` 开头，故采用 `MENGNIU_AGENT_API_TOKEN`。`.env.example` 只是变量说明；本服务不会自动加载 `.env` 文件。

公开访问使用 HTTPS。凭证不会返回浏览器，服务不接受请求方自报的访客身份，只依据安全 Cookie 生成隔离标识。首次访问会生成新的访客身份；旧 Sites 域名的访客会话不会自动迁移。

## 无模型验收

可检查网页、`/healthz` 和 `/api/bridge` 的健康状态；可在独立模拟访客空间检查任务创建、登记资料与刷新恢复。不要为了验收静态页面而点击“运行五阶段分析”或“补充资料并更新”。

本仓库的 `npm test` 只连接本地模拟服务，可验证 HTTP 边界、Cookie 隔离和来源限制。2026-10-15 的正式服务验收记录见 `verification/deployment-checks-20261015.json`；它是当时的历史记录，不代表服务永久可用，也不证明模型效果或商业效果。
